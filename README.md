# go-reservation-waitlist

本项目用于 GSB 评测，实现带"名额保留期限"的预约候补晋级队列。

## 模型

- `Waitlist` 持有固定数量的名额槽位（`slot-N`），候补申请按 FIFO 排队。
- `Promote` 为队首申请保留一个空闲槽位并生成晋级记录 `Promotion`，记录
  名额（`SlotID`）、候补版本（`Version`）、确认截止时间（`Deadline`）和
  通知编号（`NotificationID`）。
- 申请人需在截止时间前 `Confirm`（含边界，`now <= Deadline` 有效），也可
  `Decline` 主动放弃；`Scan(now)` 负责把超时未确认的晋级置为过期并释放名额。

## 并发与一致性

- 所有状态变更在单把互斥锁下完成。确认、放弃、超时扫描对同一晋级只能产生
  一个终态（confirmed / declined / expired），名额最多被占用或释放一次，
  每次变动都写入槽位台账 `SlotEvent`（动作 + 原因）。
- 候补条件变化（加入、退出、晋级、放弃、过期）会推进候补版本号；旧版本
  的晋级再确认时返回 `ErrStaleVersion`。
- 超时或放弃释放名额后，`Scan` 按当前队列快照依次晋级下一位；已明确放弃
  或过期的申请已离开队列，不会被同一次或后续扫描再次晋级。

## 幂等

- `Promote` 以 `PromoteRequest.ID` 为幂等键：相同晋级号、相同内容（通知
  编号、名额、截止时间）重放返回原记录；名额或截止时间变化返回
  `ErrConflict`。
- `Confirm` / `Decline` 对已达同一终态的晋级重放返回原结果；跨终态操作
  返回 `ErrClosed`。

## 查询

`View()` 返回一致快照：候补顺序（`Queue`）、每次晋级及其确认结果
（`Promotions`）、槽位占用（`Slots`）和名额变动原因（`Events`）。

## 测试

```sh
go test -race ./...
```

覆盖确认边界（含截止时间恰等/超过）、版本过期拒绝、超时释放并晋级下一
位、放弃者不被重复晋级、重复扫描空操作、确认/放弃/扫描并发争抢唯一终
态，以及幂等重放与冲突。

新增用例覆盖：入队快照与同版本稳定顺序、重排预览的位置变化与原因、
同号重放/规则冲突/基线失效（新增、放弃、晋级、资格变化四种基线变化）、
确认后一次性发布新版本、保留期 offer 不被重排撤销或换人、新规则下扫描
按新顺序发放且不重复晋级、`BaseVersion` 版本钉选、`View` 展示规则/变化/
依据，以及预览、扫描、放弃并发时的原子性与唯一晋级。

## 优先级规则版本

- 排序由 `Rule` 描述：`Version` 标识不可变版本，`Criteria` 是有明确先后
  顺序的条件链（当前支持 `wait-time`、`tier`、`score`；前者相等才继续
  比较下一条，全部相等再以入队序号和申请 ID 兜底）。内置默认规则
  `v1 = [wait-time]`，与原有 FIFO 行为一致。
- `JoinWith(id, Qualification{...}, now)` 入队时保存资格信息（等级、
  分数）、入队时间，以及当时规则版本推导出的排序依据 `Basis`
  （如 `tier=2`、`wait-time=...`、`seq=3`）。同一规则版本下排序稳定：
  相同条件值的申请严格按入队顺序排列。`Join` 作为零资格的便捷封装保留。
- `UpdateQualification` 记录资格变化并按当前规则重新排位。

## 重排预览与安全发布

- `PreviewReorder(ReorderRequest{ID, Rule})` 对**仍在等待**的申请计算新
  顺序，返回 `ReorderPreview`：新顺序、相对当前队列的 `PositionChange`
  （`From`/`To`/`Reason`，原因指出由哪条条件、与谁比较导致移动）以及
  绑定的规则和基线版本 `BaselineVersion`；预览阶段当前队列不变。
- 已晋级的申请（含名额保留期内 pending 的 offer）不参与重排：其晋级结果
  和保留的槽位在发布后保持不变，槽位不会被静默收回或交给别人；发布时把
  pending offer 的确认版本锚定到新版本，保留期内仍可正常 `Confirm`。
- `CommitReorder(previewID)` 在管理员确认后原子发布新队列版本：校验基线
  未变并按预览整体应用顺序，随后推进版本号、更新当前规则与各申请的排序
  快照。任何基线变化（新申请、放弃、晋级、资格变化、名额释放/过期）都会
  使旧预览失效，提交返回 `ErrStaleVersion`，不会只应用其中一部分结果。

## 重排号幂等与冲突

- 同一重排号、相同规则、相同基线：重放返回原预览；已发布的重放返回原
  发布结果。
- 同号但规则内容不同：返回 `ErrConflict`；同号同规则但队列基线已变化：
  返回 `ErrStaleVersion`（记录保留，不会被当成新预览静默重建）。

## 并发一致性

- 所有状态变更仍在单把互斥锁下完成；晋级扫描、申请放弃、重排发布都基于
  同一队列版本串行化。`PromoteRequest.BaseVersion` 可将发名额操作钉在
  观察到的版本上，版本已变化时返回 `ErrStaleVersion`，旧扫描不会按旧顺序
  继续发放名额。
- 已离开等待队列（晋级、放弃、过期）的申请不会因新规则被重复晋级；晋级
  记录同时保存 `RuleVersion` 和 `Basis` 作为晋级依据。

## 查询扩展

`View()` 除原有字段外还返回：`Rule`（当前采用规则）、队列中每个申请的
资格/规则版本/排序依据、每次晋级的规则版本与依据、`LastReorder`（最近
一次发布的位置变化）以及 `OutstandingPreview`（尚未发布的预览）。
