# go-reservation-waitlist

本项目用于 GSB 评测，实现带"名额保留期限"的预约候补晋级队列。

## 模型

- `Waitlist` 持有固定数量的名额槽位（`slot-N`），候补申请按 FIFO 排队。
- `Promote` 为队首申请保留一个空闲槽位并生成晋级记录 `Promotion`，记录
  名额（`SlotID`）、候补版本（`Version`）、确认截止时间（`Deadline`）和
  通知编号（`NotificationID`）。
- 申请人需在截止时间前 `Confirm`（含边界，`now <= Deadline` 有效），也可
  `Decline` 主动放弃；`Scan(now)` 负责把超时未确认的晋级置为过期并释放名额。

## 优先级快照与规则版本

- 排序规则是若干有严格先后顺序的条件 `Condition`（`eligible` /
  `priority` / `score` / `member` / `joined` / `id`，末尾自动追加全局入队
  序号 `seq` 作为稳定决胜项），装入不可变的 `RuleSet` 并分配单调版本号；
  规则一经安装永不修改，发布新规则只会产生新版本，可用 `Rule(version)`
  查询任意历史版本。
- 入队时（`JoinWithProfile`）冻结资格快照 `AppProfile`、当时的规则版本
  （`Application.RuleVersion`）和全局唯一入队序号（`Seq`）；同一规则版本
  下，相同快照集合必然得到稳定、确定的顺序。`Join` 等价于空快照入队。
- 新规则发布后，新入队申请按当前活动规则有序插入；默认规则
  （`DefaultRules`，仅 `seq`）保持原有 FIFO 行为。

## 安全重排

1. `PrepareReorder(ReorderRequest{ID, Conditions})` 注册新规则版本，并仅对
   **尚未晋级**的申请生成不可变重排预览 `ReorderPreview`：基线队列版本、
   基线规则版本、新顺序，以及每个申请的 `PositionChange`（原位置、新位置
   和决定移动的字段对比原因）。处于名额保留期（pending）的晋级不参与重排，
   其槽位保留与晋级结果绝不会被静默撤销或转交给他人。
2. 管理员用 `PublishReorder(id)` 一次性原子发布新队列版本：整体替换等待
   队列顺序、切换活动规则、推进 `QueueVersion`；发布后保留期中的晋级仍可
   正常 `Confirm`，其名额不会被高优先级申请"抢走"。
3. 确认前若发生入队、放弃、晋级、超时释放等任何基线变化，预览立即失效：
   `PublishReorder` 返回 `ErrPreviewGone` 且**不应用任何一部分**排序结果，
   `Preview` 也无法再取到，必须重新准备。
- 幂等与冲突：同一重排号、相同条件、相同基线重放返回原预览；条件变化返回
  `ErrConflict`；队列版本已漂移返回 `ErrStaleVersion`（失效元数据仍保留以
  区分冲突与过期）。已发布的重排号不可重复发布。

## 统一版本与并发

- `View` 同时给出总版本 `Version`、队列版本 `QueueVersion`、活动规则
  `RuleVersion`、当前顺序（`Queue` / `QueueView()` 带 1 基位置和资格快
  照）、最近一次发布的 `Changes`，以及每次晋级的 `PromotionBasis`（晋级
  时位置、规则版本和各条件取值）。
- 晋级扫描、申请放弃、重排发布在同一把互斥锁下串行，并且都以**当前队列
  版本**为准：旧扫描不可能按旧顺序继续发名额；离开等待队列（已晋级/放
  弃/过期）的申请不会被新规则再次晋级；每次晋级都记录所依据的规则版本。

## 并发与一致性

- 所有状态变更在单把互斥锁下完成。确认、放弃、超时扫描对同一晋级只能产生
  一个终态（confirmed / declined / expired），名额最多被占用或释放一次，
  每次变动都写入槽位台账 `SlotEvent`（动作 + 原因）。
- 候补条件变化（加入、退出、晋级、放弃、过期）会推进候补版本号；旧版本
  的晋级再确认时返回 `ErrStaleVersion`。
- 超时或放弃释放名额后，`Scan` 按当前队列快照依次晋级下一位；已明确放弃
  或过期的申请已离开队列，不会被同一次或后续扫描再次晋级。

## 幂等

- `Promote` 以 `PromoteRequest.ID` 为幂等键：相同晋级号、相同内容（通知
  编号、名额、截止时间）重放返回原记录；名额或截止时间变化返回
  `ErrConflict`。
- `Confirm` / `Decline` 对已达同一终态的晋级重放返回原结果；跨终态操作
  返回 `ErrClosed`。

## 查询

`View()` 返回一致快照：候补顺序（`Queue`）、每次晋级及其确认结果
（`Promotions`）、槽位占用（`Slots`）和名额变动原因（`Events`）。

## 测试

```sh
go test -race ./...
```

覆盖确认边界（含截止时间恰等/超过）、版本过期拒绝、超时释放并晋级下一
位、放弃者不被重复晋级、重复扫描空操作、确认/放弃/扫描并发争抢唯一终
态，以及幂等重放与冲突。

优先级快照与安全重排部分另覆盖：入队快照冻结与同版本稳定顺序、重排预览
位置变化与原因、原子发布及发布后按新规则有序插入、保留期晋级不被撤销且
仍可确认、加入/放弃/晋级/释放导致预览失效且失败发布零落地、重排号重放
冲突与基线漂移、扫描按发布后顺序晋级且不重复晋级、扫描/放弃/重排并发下
队列与槽位一致，以及规则版本不可变。
